Projects

Agent Write Gateway

2026.08 - 現在 / 個人開発（OSS・Apache-2.0）

人・CI・CLI・AIエージェントのいずれから来た変更要求も、同じ決定論的な安全境界を通して 計画、認可、実行、検証、停止、監査するための Change Execution Control Plane です。 現在はプロトタイプ段階で、外部への書き込みは行わないモックアダプタを用いて、安全性の性質そのものを検証しながら設計を固めています。

  • Go
  • Temporal
  • PostgreSQL
  • OPA
  • OIDC
  • REST
  • Docker Compose
  • ADR
課題設定

AIエージェントに書き込み権限を渡すと、任意のシェルや任意のHTTPを叩ける状態になりがちです。 エージェントに渡すのは署名され範囲を絞られた実行許可だけにし、 本物の資格情報は顧客環境から出さない構成を目指しています。

安全側に倒す設計

未知の参照、未知のスキーマバージョン、想定外の権限はすべて拒否側に倒します。 Contract・Profile・Planを正規化してハッシュ化し、承認をそのハッシュに紐づけることで、 承認後に中身が差し替わった状態では実行できないようにしました。

実行の耐久性

Temporalでワークフロー履歴を永続化し、一時停止・再開・キャンセル・リトライ・復旧を扱えるようにしています。 監査ログはoutboxと同一トランザクションで書き込み、実行の冪等性はDBの制約側で担保しています。

責務の分割

Control PlaneとRunnerを分離し、Runnerは署名済みの実行許可のみを受け取ります。 受け取った側でもポリシーを再評価し、短命な資格情報を取得して型付きアダプタを呼ぶ構成にしており、 任意のコマンド実行や汎用のクラウドAPIは意図的に公開していません。

GitHubで見てほしい点

internal/grant、internal/runner、internal/policy を見てほしいです。 署名検証、ポリシー再評価、nonceジャーナル、資格情報の取得、アダプタ呼び出しを、この順序でしか通れないよう実装しています。 設計判断は docs/adr に6本、脅威モデルは docs/security に残しています。

MuchUp Project

2025.06 - 現在

MuchUpは、AIがアイスブレイクを支援し、人間同士のコミュニケーションを促進するリアルタイムチャットアプリです。 ユーザーは共通の趣味やプロフィールをもとにランダムでマッチングされ、初対面の相手と会話を始めます。 AIは会話の主役ではなく、司会者として話題提供、深掘り質問、ミッション提示を行い、自然に話しやすい場を作ります。 個人利用だけでなく、企業やチームのオンボーディング用途も想定しています。

  • Go

  • gRPC
  • Protocol Buffers
  • Redis
  • REST
  • Docker
  • ADR
  • Team Development
設計判断

クライアントとのリアルタイム通信にはWebSocket、サービス間通信にはgRPC、 外部向けAPIにはRESTを使用しています。 最新状態はRedis、永続化が必要な情報はDB、履歴性や再処理が必要なイベントはRedis Streamsで扱う方針です。
